# Fork-local Subscription Account tokens

The fork supports Claude long-lived tokens beside provider-owned login accounts. Settings → AI runs `claude setup-token` in a private account home using a bounded terminal. The owner approves the provider browser page; Buzz captures the transcript in bounded zeroizing buffers, validates the token format and classifies the existing inference probe without returning provider response text. A failed or cancelled mint never publishes its credential. The provider requires human browser authorization: this is a guided renewal flow, not unattended token rotation.

The fixed `oauth-token` file is written with 0600 permissions by temp-write, fsync, direct rename and directory sync; credential targets are never canonicalized through symlinks. Metadata and every IPC DTO exclude the token. The existing 108-character normalization helper is reused with rejected buffers zeroized; the inference helper now reports a fixed 401 classification. Quota and transport errors are not declared authentication failures. The legacy Keychain store, fingerprint helper and migration bindings remain for existing users; no legacy credential is read or deleted by adding this account kind.

Desktop removes caller credential overrides, validates configuration auth conflicts, and supplies the chosen token. ACP independently reads the selected private file at the final child-spawn boundary after stripping late caller overrides. Token accounts keep per-agent Claude configuration but omit the account-specific secure-storage split. Missing, unreadable, unsafe or expired selected credentials refuse launch visibly. They never select Ambient implicitly. Token accounts have no exclusive-consumer lease, reservation, preflight or imposed account consumer ceiling. Login accounts retain their repaired exclusive behavior.

Renewal preserves account id and nickname. Completion is fenced by the mint attempt before changing the token; restart checks the still-selected account and mint under the existing runtime/store/lifecycle locks. Busy or failed restarts remain visible with recovery by selecting the same account again after the active turn finishes. Only still-bound agents are considered. No sharing consumer records, maintenance intent or auth epoch were introduced.

`minted_at` is the successful local mint-completion time in UNIX seconds. `expires_at = minted_at + 365 * 86400 = minted_at + 31536000`. Settings and Runtime use `ceil((expires_at - now) / 86400)` while positive, otherwise Expired. This is the instructed 365-day tracker, not a token-decoded provider expiry. Reminders are local only: OS notifications while Desktop runs, plus the persistent Settings card and Runtime expiry label. The first due reminder requests OS permission through the existing native notification path; minting does not request it. Durable boundary state suppresses relaunch duplicates and retains retries for failed/denied delivery. Missed thresholds collapse to the most urgent notice, each including exact UTC expiry. Nothing is posted to the relay or signed as the owner. The macOS notification helper supplies real OS permission behavior because the plugin's desktop permission method is a stub.

Source tests use synthetic provider/credential fixtures. Browser tests use mock IPC and do not establish provider or installed acceptance. Installed acceptance requires the owner minting two tokens through the UI, then an agent completing turns in two communities with one token. No concurrent-refresh proof applies to token accounts.

Provider source: [Claude Code authentication: generate a long-lived token](https://code.claude.com/docs/en/authentication#generate-a-long-lived-token), checked 2026-09-05. It describes one-year setup tokens, browser approval and terminal output without provider-side local saving. The token only supports model requests; locally configured MCP servers remain available.
